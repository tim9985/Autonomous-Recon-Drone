# 서버 설정 적용 결과 — 2026-10-04

기준: `docs/drone_server_handover_v1.1.md`. 기존 `/home/se/sandboxes/drone-server-20261003` 배포를 유지하면서 설정을 보완했습니다.

## 적용 사항

- Ubuntu 24.04 기반 이미지의 digest, PostGIS·MediaMTX digest 고정.
- 다음 재구축에서 Python `requirements.lock`을 실제 설치 입력으로 사용.
- JupyterLab·Vision worker 헬스체크 추가.
- `/health/components`에서 Jupyter·미디어 API·worker 상태와 모델 미연결 상태 조회.
- Docker stdout/stderr 로그를 컨테이너별 10MB × 3개로 제한.
- JupyterLab 시작 로그의 토큰 값 가림, 기존 토큰 로그인 유지.
- `scripts/doctor.sh`, `backup.sh`, `verify-backup.sh`, `sync-workspace.sh` 제공.

현재 실행 이미지는 이전 검증 이미지와 동일합니다. 전체 GPU 이미지의 재빌드는 수행하지 않았으며, 수정한 Dockerfile은 BuildKit의 정적 검사에서 경고 없이 통과했습니다. Python 패키지 검사도 통과했습니다.

## 검증

- 변경 전 원격/로컬 핵심 파일 SHA-256 일치, 기존 서비스 정상 상태 확인.
- Compose 검증, Bash 문법 검사, Python 컴파일, `pip check` 통과.
- 서비스 설정 재적용 후 API·DB·Jupyter·Vision worker 정상 기동.
- Jupyter 토큰 로그인과 시작 로그 토큰 미포함 확인.
- worker 상태 파일 없음·오래됨·손상 상태를 정상 상태로 표시하지 않는 시험 통과.
- 변경 전 DB 백업의 SHA-256 확인 및 새 임시 DB 복원 성공. 기존 DB는 덮어쓰지 않음.
- 원본 녹화 자동 삭제 비활성화 유지. 기존 영상 해시 유지 확인.
- DB·관리 API·Jupyter·SRT는 기존 localhost 바인딩 유지.
- 설정 적용 과정에서 호스트 GPU 작업을 중단하거나 호스트·전용 엔진을 재부팅하지 않음.

증거는 서버와 로컬 프로젝트의 `evidence/20261004/`에 보관합니다. 백업은 서버 `data/backups/`에만 보관하며 인증 비밀 값과 원본 영상은 백업 묶음에 포함하지 않습니다.

## 미완료 사항

모델 가중치와 종류가 제공되지 않아 실제 추론 연결은 대기 상태이며 `model_loaded=false`, `flight_enabled=false`를 유지합니다. 현재 상태 페이지를 인증된 모바일 관제로 간주하지 않습니다. 운영자 로그인·권한·임무 및 안전 상태기·복구 업로드는 별도 구현이 필요합니다.

학교의 외부 HTTPS/WSS·SRT UDP/VPN 경로, TLS, 5TB 할당·보존 정책은 관리자 확인이 필요합니다. 이를 추정해 공개 포트나 방화벽을 변경하지 않았습니다.
